# Архитектура проекта

## 1. Обзор

Проект построен по **модульному принципу**. Каждый этап обработки имеет собственную ответственность и передаёт следующему этапу структурированные данные.

Это позволяет:

- тестировать компоненты независимо;
- заменять или расширять конкретный этап без полной переработки;
- масштабировать функциональность.

## 3. Модули

### 3.1. Parser (`parser/`)

Анализирует PowerPoint-шаблон, извлекает дизайн-систему.

**Точка входа:** `parser/parse_template.py`, функция `parse_template()`.

**Подмодули:**
- `theme_parser.py` — цвета, шрифты;
- `master_parser.py` — master-слайды;
- `layout_parser.py` — layouts;
- `slide_parser.py` — существующие слайды;
- `grid_extractor.py` — сетка;
- `pattern_clusterer.py` — кластеризация паттернов.

**Результат:** `DesignSystem`.

### 3.2. Generation (`generation/`)

Отвечает за создание содержимого и визуальную компоновку.

**Подмодули:**
- `plan_content.py` — планирование содержания;
- `layout_engine.py` — раскладка элементов;
- `slide_builder.py` — сборка слайдов;
- `export/` — экспорт в `.pptx`, `.pdf`, `.html`.

### 3.3. Audit (`audit/`)

Проверяет результат генерации на наличие проблем.

**Точка входа:** `audit/audit.py`, функция `run_audit()`.

**Подмодули:**
- `deterministic/` — механические проверки (6 штук);
- `contextual/` — VLM-проверки;
- `repair.py` — исправление;
- `render.py` — рендер слайда в изображение.

Подробнее — в `AUDIT.md`.

### 3.4. Shared (`shared/`)

Общие модели данных, константы, утилиты.

**Подмодули:**
- `schemas/` — модели (`DesignSystem`, `Presentation`, `SlidePlan`, `AuditReport`, `Issue`);
- `utils/` — утилиты (`emu.py`, `color.py`, `geometry.py`, `constants.py`).

### 3.5. Pipeline (`pipeline/`)

Объединяет все модули в единый процесс.

**Точка входа:** `pipeline/run.py`.

### 3.6. API (`api/`)

Серверная часть.

**Точка входа:** `api/server.py`.

### 3.7. Frontend (`frontend/`)

Веб-интерфейс на Next.js.

## 5. Ключевые решения

### 5.1. Модульность

Каждый этап — отдельный модуль. Можно заменить любой, не трогая остальные.

### 5.2. Промежуточные модели

Между модулями передаются структурированные данные (`DesignSystem`, `SlidePlan`, `AuditReport`). Это позволяет тестировать компоненты по отдельности.

### 5.3. Аудит как отдельный этап

Аудит вынесен в отдельный модуль. Он работает после генерации и до экспорта. Может запускаться повторно после repair.

### 5.4. Два типа проверок

Детерминированные (быстрые, точные) + контекстные (VLM, смысловые). Комбинация даёт лучшее покрытие.

### 5.5. Промпты отдельно от кода

Промпты AI-компонентов хранятся в `prompts/*.md`. Это позволяет менять поведение моделей без изменения кода.

## 6. Технологический стек

- **Python** ≥ 3.10;
- **python-pptx** — работа с `.pptx`;
- **lxml** — обработка XML;
- **Pydantic v2** — модели данных;
- **OpenAI** — AI-интеграция;
- **FastAPI** — серверная часть;
- **Next.js** — веб-интерфейс;
- **pytest** — тестирование.

## 7. Расширяемость

Чтобы добавить новый тип проверки:

1. Создать файл в `audit/deterministic/`.
2. Реализовать функцию `check_*(presentation, design_system) -> list[Issue]`.
3. Добавить в `audit/deterministic/__init__.py`.
4. Добавить в `audit/audit.py`.

Чтобы добавить новый тип builder:

1. Создать файл в `generation/`.
2. Реализовать функцию `build_*`.
3. Подключить в `slide_builder.py`.
